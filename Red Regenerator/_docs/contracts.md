# Contracts

A **Sales Contract** or **Purchase Contract** is a recurring billing document — the
same kind of document as a Sales/Purchase Order or Invoice, but flagged with a
special document type ("Red Regenerator") and never posted itself. Instead, on a
schedule you set up, it spawns a real Order or Invoice for the amount due that
period. Use it for anything billed on a repeating schedule: software licenses,
extended warranties, rentals, service contracts, and similar.

Sales Contracts live on the **Sales Contracts** list, Purchase Contracts on the
**Purchase Contracts** list. Each opens on its own card (**Sales Contract** /
**Purchase Contract**), which looks and behaves like a regular Order.

## Contract fields

- **Group** — the contract's [Contract Group](contract-groups-and-setup.md#contract-groups),
  which decides whether regenerating the contract creates an Order or an Invoice.
- **Start Date** — when the contract begins.
- **Duration** — a date formula (for example `1Y` or `6M`) for how long the contract
  runs. Leave it blank for a contract that runs indefinitely.
- **End Date** — calculated automatically from Start Date + Duration; not editable.
- **Billing Period** — a date formula for how often the contract is billed (for
  example `1M` for monthly). Defaults to the Duration if you don't set one.
- **Next Billing Date** — the date the next regeneration will use as its posting
  date; not editable directly.
- **Contract Iteration** — how many times the contract has been billed so far.
- **Contract Status** — see below.

Changing the Start Date or Duration is only allowed while the contract is in
**Concept**, **Expired**, or **Auto Generated** status — once it's Accepted or
Active, those fields are locked in.

## Contract status

```
Concept ──Accept──► Accepted ──Activate──► Active ──(billing period elapses)──► Expired
                                              │                                    │
                                              ├──Close───────────────────────► Closed
                                              ├──Cancel──────────────────────► Canceled
                                              └──Renew (from Active/Expired/Closed)──► Active
```

- **Concept** — a draft contract. Fields can still be edited freely.
- **Accepted** — you've committed to the contract; it has generated its first
  billing document.
- **Active** — the contract is live and will keep generating billing documents on
  its Billing Period.
- **Expired** — the contract's Next Billing Date has passed its End Date; no more
  documents will be generated until it's renewed.
- **Closed** / **Canceled** — the contract has been ended manually and won't be
  billed again.
- **Auto Generated** — a contract created automatically from a [Contract
  Template](creating-contracts.md#automatic-contracts-from-templates) rather than
  by hand. It behaves like Concept, except it can be activated directly without
  going through Accept first.

## Actions

- **Accept** — moves a Concept contract to Accepted and immediately generates its
  first billing document (Order or Invoice, per the contract's Group). Requires
  Start Date, Billing Period, and Group to be filled in first.
- **Activate** — moves an Accepted or Auto Generated contract to Active. This
  happens automatically the moment the order/invoice generated by Accept is
  posted, so you rarely need to click it by hand.
- **Regenerate** — creates the next billing document (Order or Invoice) for an
  Active contract, using the Next Billing Date as its posting date, then advances
  Next Billing Date by one Billing Period. Blocked if a document already exists
  for the current Contract Iteration (so you can't accidentally bill the same
  period twice), or if billing would run past the End Date.
- **Regenerate and Post** — same as Regenerate; also intended to post the
  resulting document (this half of the action is not implemented yet, so today
  it behaves the same as Regenerate).
- **Renew** — extends an Active, Expired, or Closed contract's End Date by one
  more Duration and returns it to Active, so it starts billing again. Optionally
  archives the contract first, per [setup](contract-groups-and-setup.md#setup).
- **Close** — offered once a contract has Expired. Ends the contract and, per
  setup, may archive it (and optionally delete it after archiving).
- **Cancel** — offered while a contract is Accepted or Active. Ends the contract
  early and, per setup, may archive it (and optionally delete it after archiving).

Regenerate, Renew, Close, and Cancel all refuse to run if the contract's Group
isn't set, or (for Regenerate/Renew) if the contract isn't Active.

## Original Document

If the contract was created automatically from a regular sales/purchase document
(see [Creating Contracts](creating-contracts.md)), its card shows an **Original
Document** action that jumps to the order/invoice — or its posted shipment/receipt
— that the contract was generated from.

## Approvals

Contracts use Business Central's standard approval workflow (Send Approval
Request / Cancel Approval Request / Approve / Reject / Delegate / Comments) if
your company has approval workflows set up for sales/purchase documents.
